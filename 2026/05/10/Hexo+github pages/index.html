从零开始：用 GitHub + Hexo 搭建你的免费个人网站

一、准备工作

在开始之前，我们需要准备三样东西。

1.1 注册 GitHub 账号

访问 github.com 注册一个账号。用户名建议用英文，因为后续你的网站地址会是 用户名.github.io，这个名字就是你的门面。

1.2 安装 Node.js

Hexo 是运行在 Node.js 上的，所以需要先安装 Node.js。

  1. 访问 nodejs.org，下载 LTS（长期支持版）；
  2. 一路”下一步”安装完成；

能看到版本号（例如 v20.x.x 和 10.x.x）就说明安装成功。

1.3 安装 Git

Git 用于把博客源码推送到 GitHub。

  1. 访问 git-scm.com 下载安装；
  2. 安装完成后验证：

1.4 准备一个友好的目录

准备一个不含中文的目录来放博客项目，例如 D:\blog 或 C:\blog。避免中文路径能省掉很多莫名其妙的报错。

二、认识 Hexo 与整体工作流

Hexo 是什么？

Hexo 是一个静态网站生成器：你用 Markdown 写文章，它负责把 Markdown 渲染成一个个 HTML 网页文件。这些文件不需要数据库、不需要后端，随便一个静态服务器都能托管，而 GitHub Pages 恰好提供了免费的静态托管。

简单来讲，就是把markdown文章渲染为HTML代码(hexo g)，之后push HTML 代码到Github仓库(hexo d)，通过Github Pages进行展示。

整体工作流

写作 → 生成 → 部署 → 上线，每次更新博客都是这四个步骤。

6.4 验证访问

浏览器打开 https://你的用户名.github.io，能看到你的博客就说明部署成功了。第一次部署后 GitHub Pages 生效需要几分钟，稍等再刷新。

6.5 常见部署坑

现象原因与解决
404 页面仓库名必须和用户名一致；部署后等几分钟再刷新
改了代码线上没变化先 hexo clean 再重新生成部署；检查是否推错了分支
部署时报权限错误确认 deploy.repo 地址正确，仓库名大小写敏感
